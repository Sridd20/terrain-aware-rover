1. Architecture at a Glance
Two layers, connected over WiFi/MQTT:
EE layer (on the rover): MPU6050 → ESP32 → L298N → 2× DC motors
CS layer (laptop/Pi during development, optional once inference moves fully on-device): MQTT ingest → windowing → feature extraction → classifier → smoothing → speed policy → dashboard
Target end-state: the classifier and control loop run entirely on the ESP32 (Section 5 covers exporting the trained model to C++). The laptop-side pipeline is used during development, data collection, and training, and optionally kept for the live dashboard.

3. Firmware Module (ESP32 / C++)
3.1 Sampling loop
Sample the IMU at 100 Hz on a fixed timer. Maintain a circular buffer of the last 100 samples (1 second of data).
const int WINDOW_SIZE = 100;      // 1s @ 100Hz
float window[WINDOW_SIZE];
int windowIdx = 0;
const unsigned long SAMPLE_PERIOD_MS = 10;   // 100 Hz
 
void loop() {
  if (millis() - lastSample >= SAMPLE_PERIOD_MS) {
    lastSample = millis();
    float z = readAccelZ();               // from MPU6050
    window[windowIdx % WINDOW_SIZE] = z;
    windowIdx++;
    if (windowIdx >= WINDOW_SIZE) runInferenceCycle();
  }
}
3.2 Feature extraction (5-D vector)
Computed once per window (every ~10 new samples for 50% overlap in the training pipeline; on-device this can run every window for simplicity).
Feature
Formula
Why it matters
std
standard deviation of the window
Primary discriminator — vibration intensity
rms
sqrt(mean(x²))
Overall energy, orientation-independent
peak
max(|x|) / rms
Impulsiveness — separates spiky gravel from smooth carpet
p2p
max(x) − min(x)
Range of motion within the window
zcr
count of sign changes between consecutive samples
Cheap proxy for dominant frequency
void extractFeatures(float *buf, int n, float *out5) {
  float mean = 0, sq = 0, mx = buf[0], mn = buf[0], rmsAcc = 0;
  for (int i = 0; i < n; i++) {
    mean += buf[i]; rmsAcc += buf[i] * buf[i];
    if (buf[i] > mx) mx = buf[i];
    if (buf[i] < mn) mn = buf[i];
  }
  mean /= n;
  float rms = sqrt(rmsAcc / n);
  for (int i = 0; i < n; i++) sq += (buf[i]-mean)*(buf[i]-mean);
  float std = sqrt(sq / n);
  float peak = rms > 0.001 ? max(fabs(mx), fabs(mn)) / rms : 0;
  int zcr = 0;
  for (int i = 0; i < n-1; i++) if (buf[i]*buf[i+1] < 0) zcr++;
  out5[0]=std; out5[1]=peak; out5[2]=rms; out5[3]=mx-mn; out5[4]=(float)zcr;
}
3.3 Classifier integration
The trained scikit-learn decision tree is exported to a C++ header (see Section 5.3) and included directly in firmware:
#include "terrain_classifier.h"
Eloquent::ML::Port::DecisionTree clf;
 
const char* label = clf.predictLabel(features);   // "tile" | "mat" | "carpet" | "gravel"
Do not hand-edit this header. Regenerate it whenever the model is retrained (Section 5.4).

4. ML Training Pipeline (Python)
4.1 Data collection protocol
4 classes: tile, mat, carpet, gravel
4 × 3-minute sessions per class, on separate days — not one long run
3 PWM levels (low/med/high) per class, so the model learns terrain, not speed
Split by session, not by window — train on sessions 1–3, hold out session 4 (prevents inflated accuracy from overlapping windows leaking into test)
4.2 Feature extraction (Python, mirrors Section 3.2)
def extract_features(sig):
    std = sig.std()
    rms = np.sqrt((sig**2).mean())
    peak = np.abs(sig).max() / rms if rms > 1e-3 else 0
    p2p = sig.max() - sig.min()
    zcr = ((sig[:-1] * sig[1:]) < 0).sum()
    return [std, peak, rms, p2p, zcr]
4.3 Model selection
Start with DecisionTreeClassifier(max_depth=5) — interpretable, prints as a readable tree
Compare against KNN (k=5) and RandomForest (100 trees) via session-wise cross-validation
Pick the simplest model within ~2% of the best accuracy
Report a confusion matrix — expect carpet/mat to be the most confusable pair
4.4 Exporting to C++
Use micromlgen (or scikit-learn's own tree export, hand-adapted) to convert the trained tree into the header used in Section 3.3:
from micromlgen import port
cpp_code = port(clf, classmap={0:'tile', 1:'mat', 2:'carpet', 3:'gravel'})
with open('terrain_classifier.h', 'w') as f:
    f.write(cpp_code)
Regenerate and replace firmware/terrain_classifier.h every time the model is retrained on new data. Do not hand-edit the generated header.

5. Dashboard Module
Subscribes to rover/state over MQTT. Minimum required views:
Live accelerometer trace (scrolling, last ~3 seconds)
Current predicted label + confidence
Current PWM / speed and active driving profile
Slope state indicator (NORMAL / DETECT / RETREAT / APPROACH / CLIMB)
Suggested stack: Flask + Chart.js, or Streamlit for faster iteration. Update rate: match MQTT message rate, no additional polling needed.
